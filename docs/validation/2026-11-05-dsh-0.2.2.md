# 2026-11-05 验证：DSH 0.2.2-rc.1（@anweat/dsh-browser 0.2.2 + 本分支）

结论：在 DSH `0.2.2-rc.1`（cordis 4.1.0、schemastery 3.19.0）上，外部 PR #48 的 peer 放宽能让插件安装并跑完整的工具调用，但**设置卡片的 RPC 通道没有挂上**（HTTP 405），PR 没有发现，因为它只验证到“激活、设置命名空间存在”。本分支在 #48 之上加了一个回退，三个宿主上都已实测。

执行者是开发者侧代理，不是独立验证者。只写亲眼看到的结果。证据在仓库外的 `research/experiments/dsh-0.2.2-2026-11-05/dsh-browser/`（`logs/`、`*.png`、`scripts/`）。

**0.2.2 正式版**：peer 上界是 `<0.2.3-0`，所以 0.2.2 正式版被放行，**靠的是 rc.1 的验证**；它没有在真实宿主上跑过。

## 环境

- 宿主：`npm i --prefix <dir> @deepseek-ai/dsh@<ver> --registry https://registry.npmjs.org`，`0.2.0-rc.2`（cordis 4.0.5）、`0.2.1-rc.5`（cordis 4.0.5）、`0.2.2-rc.1`（cordis 4.1.0，schemastery 3.19.0）。
- 插件：`pnpm pack` 的 tgz，`dsh plugin --profile <p> add file:<tgz>`（过安装闸门），嵌套 pnpm 11.7.0（PATH 垫片）。
- 每个宿主一个全新 `DSH_HOME`（scratchpad 下），空的 `PLAYWRIGHT_BROWSERS_PATH`，没有读写 `~/.dsh`，没有占 19387（Web 用 3398 / 3397 / 3396），没有跑模型、登录类命令、opencli 站点命令，没有读凭据。

## 2. headless：完整工具调用（无模型）

探针是一次性插件（`scripts/probe-plugin/`，scratchpad，不在仓库里），启动后用宿主的 `ctx.tools.execute` 调工具，判定标准是**完成的工具调用结果**。0.2.2-rc.1 的 `ctx.tools.execute` 签名变了（现在是 `{ calls: [{id, name, arguments: JSON 字符串}], signal }`，返回 `results[i].result`），探针按版本适配；这是宿主 API 变化，插件不调用它。

每个宿主各跑两次：**没有配置的 entry**（profile 的 patch 为空）与**有配置的 entry**（profile patch 里 `maxSessions: 3`、`headless: true`、`snapshotDir`、`prompts.rootGuide`）。每次 9 步：`browser_index`、`runtime.status`、`target.open`（本地 127.0.0.1 fixture 页面）、`observe.read`、`observe.screenshot`、volatile 编辑、再 `browser_index`、`runtime.status`、`target.list`，最后 `target.close`；探针里还有一步 `act.click`（standard 模式要求审批）。

| 宿主 | 无配置 | 有配置 |
|---|---|---|
| 0.2.0-rc.2 | 全部 `ok`，无失败 | 同左（截图落在配置的 `snapshotDir`） |
| 0.2.1-rc.5 | 同上 | 同上 |
| 0.2.2-rc.1 | 同上 | 同上 |

- volatile 编辑：用宿主的 `settings.update('browser', { prompts: { rootNote } })`，下一次 `browser_index` 立刻带上新文本（三个宿主、两种 entry 都是 `rootNoteSeen: true`），且之前打开的页面还在（`target.list` 仍有 `t1`），即插件没有重启——`prompts` 的“实时读取”在 cordis 4.1 / schemastery 3.19 上仍成立。写盘后配置 entry 里 `maxSessions` 等原有字段保留。有配置的 entry 在 overlay 覆盖时 `settings.update` 被宿主拒绝（`overridden by a home patch or command-line overlay`），这是宿主的设计，测试里改成写 profile 自己的 patch。
- `tools/pre-execute`：`act.click` 在 0.2.1-rc.5 与 0.2.2-rc.1 上给出相同的 `requires approval`（探针没有 agent 可路由），审批钩子仍在链上。
- 日志与每次的 profile patch：`logs/probe-*.json`、`logs/patch-*.yml`。

## 3. 设置卡片的 RPC 通道（真实 Web profile）

方法：`dsh --profile web --no-open --port <p>`，Playwright 驱动系统 Google Chrome 打开 插件 → `@anweat/dsh-browser`，记录对 `/dsh-browser-assets/*` 的请求。

**没有回退（#48 原样）在 0.2.2-rc.1 上**：8 个请求（`snapshot`、`prompts`、`promptsDefaults`、`policy`、`runtime`）全部 `HTTP 405`（`Allow: GET, HEAD`），控制台 8 条 405 错误。同一个插件在 0.2.1-rc.5 上全部 200。

定位：在插件里插桩，`connection.rpc.handle` 抛 `cannot get property "webServer" without inject`，异常出在 `ctx.inject` 回调里，宿主日志里没有任何输出。试过 `connectionCtx.connection`、`.root.connection`、`ctx.get('connection')` 等读法都一样；宿主的私有 `register(owner, ...)` 用注入了 `webServer` 的 Context 当 owner 就能挂上。根因在宿主 `rpc-host.ts`（`owner.webServer`），主会话确认 DSH master 在 2026-11-04 仍是这段代码。

**退化的样子**（截图 `degraded-*.png`，文本 `degraded-card-text.txt`，用“人为让回退失效”的构建）：卡片能渲染、能保存普通设置；状态摘要少了“浏览器：…”一项；提示词分组写“暂时读不到插件状态（重启中？），稍后刷新。”并显示“已覆盖”徽章；策略覆盖层写“暂时读不到覆盖层状态”；资产列表与运行状态提示取不到数据。没有一处说明是通道没挂上，提示还会把人引向“重启”。

**有回退的构建**（`logs/net-assets-*.json`）：

| 宿主 | `/dsh-browser-assets/*` | 走的路径（插桩日志） |
|---|---|---|
| 0.2.2-rc.1 | 8 个请求全 200，`snapshot` / `prompts` / `promptsDefaults` / `policy` / `runtime` 都返回 `ok:true` 的数据 | `rpc.handle` 抛错 → `register(owner)` 回退 |
| 0.2.1-rc.5 | 8 个请求全 200 | `channel mounted via rpc.handle` |
| 0.2.0-rc.2 | 8 个请求全 200 | `channel mounted via rpc.handle` |

**卸载**（0.2.2-rc.1，`scripts` 里的 dispose 探针）：挂载期间再注册同一个通道抛 `duplicate prefix route "/dsh-browser-assets"`；把 `dsh-browser` 的 fiber 全部 dispose（状态变 4）后，再注册同一个通道成功（`registered OK`），即通道随插件卸载，不残留。禁用 entry 走的是同一条 dispose 路径，没有单独用禁用操作测过。日志：`logs/dispose-0.2.2-rc.1.json`。

**回退也失效时**：人为让 `register` 不可用（只改 scratchpad 里安装的副本），Web 日志里出现一条 `dsh-browser: settings-card RPC channel /dsh-browser-assets was not mounted (cannot get property "webServer" without inject); the card's assets, prompts, policy and runtime panels will not load`，卡片退化为上面的样子（6 个 405）。日志：`logs/simulated-register-removed-host-log.txt`。这条警告是新加的：在此之前同样的失败没有任何输出。
