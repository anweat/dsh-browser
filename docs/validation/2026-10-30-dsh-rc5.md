# 2026-10-30 验证：DSH 0.2.1-rc.5（@anweat/dsh-browser 0.2.2）

结论：`@anweat/dsh-browser@0.2.2`（npm 已发布版）在新宿主 `@deepseek-ai/dsh@0.2.1-rc.5` 上干净安装、加载、设置卡片渲染与保存都正常。**插件源码与 peer 范围零改动**（`>=0.2.0-rc.2 <0.2.1-0 || >=0.2.1-rc.2 <0.2.2-0` 本来就覆盖 rc.5）。只把 rc.5 加进 `test:peers` 的受支持基线和文档里的“实测”列表。

执行者是开发者侧代理，不是独立验证者。只写亲眼看到的结果。截图、日志、脚本在仓库外的 `research/experiments/dsh-rc5-2026-10-30/`（`browser-*.png`、`logs/`、`scripts/`）。

## 被测对象与环境

- 宿主：`npm i --prefix <scratchpad> @deepseek-ai/dsh@0.2.1-rc.5 --registry https://registry.npmjs.org`（dist-tag `next`），顶层 `@deepseek-ai/cordis` 4.0.5、`@deepseek-ai/schemastery` 3.18.5，与 rc.4 的依赖版本相同。npm 在安装宿主时给出一条 `install-scripts` 提示（`node-pty`、`koffi`、`@deepseek-ai/dsh-subprocess-local`、`@google/genai`、`protobufjs` 的安装脚本没有被允许运行）；下面的检查没有用到这些脚本，宿主的 headless / web 都照常启动。
- 源码对照：`git diff dsh-v0.2.1-rc.4 dsh-v0.2.1-rc.5` 只改了 `packages/client/ui-chat` 的推理块（reasoning）渲染、`cordis-client-runner` 的 slot 目录和 `client-ui-cot-translation`，以及各包 `package.json` 的版本号（没有依赖变化）。插件用到的接口（设置 `mutate`、RPC、凭据、`tools/pre-execute`、`ui-primitives`、`plugins.bundle.config` 槽位）不在其中。
- 插件：npm 上已发布的 `@anweat/dsh-browser@0.2.2` 与 `dsh-web-search-pro@0.2.3`，像新用户一样装，不用本地 tgz。
- 隔离：每项检查用全新的 `DSH_HOME`（scratchpad 下），没有读写 `~/.dsh`，没有占用 19387（Web 用 3398 / 3399），没有碰桌面端，没有读凭据文件，没有填 API Key（首次打开的“开始使用”对话框用 Escape 关掉），没有跑模型会话、登录类命令和 opencli 站点命令。`npm_config_registry=https://registry.npmjs.org`。

## 1. 干净安装（npm 发布版）

`dsh plugin --profile <p> add @anweat/dsh-browser@0.2.2 dsh-web-search-pro@0.2.3`，web 与 headless 两个 profile，全新 `DSH_HOME`，不预写 `allowBuilds`。

| 嵌套 pnpm | web | headless | 警告 / 错误 |
|---|---|---|---|
| 11.7.0（PATH 垫片） | 退出码 0 | 退出码 0 | 无（没有 `ERR_PNPM_IGNORED_BUILDS`，没有 `pnpm-workspace.yaml` 占位） |
| 12.4.2（这台机器的默认 pnpm） | 退出码 0 | 退出码 0 | 无（只有 pnpm 的“Update available”提示） |

两种 pnpm 下 `Packages: +25`，`dsh.profile.bundles` 里都有 `@anweat/dsh-browser` 和 `dsh-web-search-pro`；`--dump-config`（headless）含两个插件的层。日志：`logs/install-npm-pnpm11.7.0-*.log`、`logs/install-npm-pnpm12.4.2-*.log`、`logs/dump-config-headless.txt`。

## 2. headless（无模型）

方法同 2026-10-28 的记录：一次性探针插件（scratchpad，不在仓库里）在启动后用宿主自己的 `ctx.tools.execute` 调工具，把结果写文件。为了不走模型，探针 profile 里关掉了 `llm-deepseek` 和 `headless-runner` 两行（否则宿主在没有 API Key 时 `MISSING_CREDENTIAL` 退出）。两个插件都加载，启动日志为空（没有 `incompatible`、没有错误）。

- 工具列表含 `browser_index`、`browser_call`、`web_index`、`web_call`（外加宿主自带的 `web_search`、`web_fetch`）。
- `browser_index({})`：1014 字符，列出 9 个分组（runtime 6、target 5、observe 2、act 11、inspect 4、script 5、automation 4、crawl 1、opencli 3）和 `mode standard`。`browser_index({group:'runtime'})` 列出动作。
- `browser_call runtime.status`：`ok: true`，`runtimeWarnings: []`，`channel: chromium`，`automationMode: standard`。
- `web_index({})`：1818 字符，列出 search / read / history / sources / rules / cache / config 分组；`web_call config.inspect` 与 `sources.status` 都成功。

日志：`logs/probe-headless-indexes.json`、`logs/probe-headless-groups-status.json`。

## 3. Web profile（Playwright，端口 3398）

方法：`dsh --profile web --no-open --port 3398`，Playwright 驱动系统 Google Chrome（无头，宽度 1100），打开 插件 → `@anweat/dsh-browser`。

| 检查 | 结果 |
|---|---|
| 卡片渲染：状态摘要（已启用 / 模式 standard / 工具面 indexed / OpenCLI 开 / 浏览器：系统 Chrome / Edge / 无警告）、九个分组（`dsb-group`，1px 边框、12px 圆角、白底）全部可展开，“常用”默认展开 | 通过 |
| 保存一项：把“启用 OpenCLI”关掉并保存 → 保存条回到“没有未保存的修改”，profile 的 `cordis.patch.yml` 里多了 `browser` 行的 `config.opencliEnabled: false` | 通过 |
| 恢复：点该行的“恢复默认”再保存 → 这一行从 patch 里消失（与保存前相同） | 通过 |
| 浏览器控制台错误、HTTP 4xx / 5xx | 0 |

截图：`browser-1-card-top.png`、`browser-2-all-open.png`、`browser-3-dirty.png`、`browser-4-saved.png`、`browser-5-restored.png`；脚本输出 `browser-tour.json`。

观察（与 rc.5 无关，已发布的 0.2.2 上就有，没有改）：全新 profile 里，“提示词”分组的标题右侧显示“已覆盖”徽章，但分组里写着“没有覆盖，全部使用默认文本”，三条文本行都是“默认”。徽章条件在 `src/client/group-prompts.tsx` 的 `PromptsGroup`（`state.overridden`）。没有在别的宿主上对比，所以不能说它只在 rc.5 出现。
