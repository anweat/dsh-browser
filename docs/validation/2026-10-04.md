## 问题、修复和保留事项

### V01 — 轻微指导遗漏，已修复

初轮提示词 6 先读 `sections=["tables","controls","links"]`，随后要求从该 journal seq 生成 extract，收到：

```text
INVALID_ARGS: extract: seq 5 did not read the page text (sections ["tables","controls","links"]); extract needs the content section
```

DS 后来补读 content 并恢复成功。源头是 skill / `automation.develop.draft_from_journal` 的说明没有写明 extract 来源必须包含 content；即使 extract 的 mode 是 links，也不能使用只读结构化 links 的 observation。

小修复：补充 SKILL.md、references/develop.md（含有效 observe.read 示例）及该子动作说明，不改变执行器或 schema。复跑提示词 6、综合 A–H 均无 INVALID_ARGS；L0 仍 325 token，最大详情层约 980 token（预算 1000）。

### V02 — 测试提示词冲突，已修正工作区文档

原提示词 1 只准 browser_index / browser_call，却预期先加载 skill。初轮 DS 明确解释按限制未调用 skill。现允许先加载 dsh-browser skill，再限定浏览器工具；复测 skillLoaded=true，两个浏览器工具。综合提示词同样修正。工作区根目录不是 Git 仓库，这份根目录文档修改不属于插件仓库提交；修正版快照随报告保存。

### V03 — 无效参数先审批，保留为流程改进项

真实 standard 表单测试中 DS 将 act.select 的 values 写成 value。Host 先出现审批，允许后工具才返回 INVALID_ARGS；模型改成 values:["pm"] 后又出现一次正确审批。

```json
{"locator":{"selector":"select[name=\"slot\"]"},"value":"pm"}
```

对应审批原文：

```text
Run a direct Playwright page interaction: act.select selector="select[name=\"slot\"]"
```

修正后审批带 `(values pm)`，最终报名成功。错误参数没有执行页面动作，但增加无意义审批；目前 action 参数校验在 runAction，晚于 tools/pre-execute 审批。若要前置，需要统一审批与执行使用的校验/错误通道，故本轮保留，不做局部绕过。属于审批体验改进，未观察到错误执行或审批泄露填写值。没有在本次范围内发现 P0/P1 功能故障。

其他观察：standard 复用用两次 automation.search 才命中中文命名资产，最终正常复用；不据单次轨迹泛化为检索质量结论。合法空结果在 nonEmpty 约束下失败是设计要求，不是 bug。
