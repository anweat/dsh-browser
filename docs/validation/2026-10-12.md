### E 策略覆盖层

- **加域名后 cookie 才注入**（全新 session，`E-unr2`）：基线只允许 `alt.localhost`，先 `target.open http://localhost:47312/whoami authProfile=fx` → `POLICY_DENIED: auth profile fx is not allowed for localhost`（`E-unr1` 步骤 2）。`runtime.set_auth_profile` 加 `localhost` 后重新打开，页面回显 `{"cookie":"sid=fx-localhost-cookie"}`。
- **撤销后立即失效且 session 被关闭**：收回 `localhost`，结果 `sessionsClosed: 1`，note “Sessions whose login state this change took away were closed”；`observe.read` 得到 `about:blank`，再次打开 `POLICY_DENIED`。`runtime.remove_auth_profile` 同样 `sessionsClosed: 1`，之后 `NOT_FOUND: unknown auth profile`。删除基线 profile `fx` 后 `inspect.policy` 给出 `removedByOverlay: ["fx"]`，`reset_policy scope=authProfile id=fx` 恢复，随后 `fx` 的 Cookie 重新可用。
- **拒绝项**（`E-unr2`，均为 `INVALID_ARGS`）：`*`（wildcard only as leading label）、`com`（bare top-level name）、`169.254.169.254`（link-local and cloud metadata … never allowed）、`localhost:47312`（host name only）、`storageStatePath=/etc/hosts.json`（outside the auth directory）、含 `..` 的路径、profile id `__proto__`（reserved object key）、新 profile 状态文件不存在且 `persistState=false`。`maxConcurrency: 9` 被拒（范围 1–8）。`expectedRevision` 过期：`the policy overlay is at revision 1, not 99`。
  - 注意：`127.0.0.1` 在 `allowPrivateHosts: true` 时被接受（设计如此，README 同写）；这次是用它验证开关语义，之后已 `reset_policy` 清理。
- **模式差异**：
  - standard（Web）：放宽 `set_auth_profile` 弹审批，原文 `runtime.set_auth_profile: Loosen a browser restriction: profile fx: allow localhost`（diff 在审批里）；收紧 `set_usage_policy`、收紧 `set_auth_profile` 无审批；批准后结果 `risk.approval: "approved by the user for this call"`。
  - autonomous（headless）：收紧直接执行；放宽 `set_auth_profile`、放宽 `set_usage_policy`、会放宽的 `reset_policy` 都是 `requires approval, but no approval channel is available`。**这与任务说明里的“autonomous/unrestricted 放行”不同，与 README 一致（autonomous 放宽仍询问）。**
  - unrestricted：全部放行，放宽结果带 `risk: {level: "elevated", loosened, approval: "none (automationMode=unrestricted does not ask)", note}`。
  - read-only：收紧直接执行（`minDelayMs 1500 -> 2500`），放宽（含回滚到更宽基线）被拒。
- **覆盖文件被篡改**（`E-tamper` 与 Web 活进程 `W1c`）：手工改动覆盖文件内容而不改校验和后，`runtime.status.runtimeWarnings` 与 `inspect.policy.warning` 都给出 `policy overlay … was ignored (the baseline configuration applies): the checksum does not match: the file was edited outside the plugin`，生效值回到基线（把 `allowedDomains` 手工改宽到 `other.localhost` 没有生效）；面板告警位显示同一句话。写动作被拒，`runtime.reset_policy` 或面板按钮清除后告警消失，坏文件改名为 `policy-overlay.json.corrupt-<时间>`。
- **面板“清除覆盖”后 agent 视角同步**：面板清除（审计 `r5 · panel · panel.reset · Cleared from the settings card`）后，另一进程里的 `inspect.policy` 立即为 `revision: 5, overlayActive: false`，限流回到基线。

## 问题、修复和保留事项

### P1-1 — 面板保存非法 context/下载值，使插件下次启动失败，且卡片消失（未修复）

最小复现：`browser-v022-web` 启动 → 打开插件详情 → “浏览器上下文”把“自定义视口宽度”清空（`viewportMode` 保持 `custom`）→ 点页面最底部“保存”→ 重启 profile。结果：

```text
browser (@anweat/dsh-browser): Error: dsh-browser config: viewportMode=custom requires both viewportWidth and viewportHeight
```

详情页只有红色“异常”，没有原因，设置卡片不再渲染，用户只能手工编辑 `cordis.patch.yml`。同一类还有 `proxyServer=ftp://…`、`downloadDir` 为相对路径（后者在 `config.ts` 里同样在加载期抛错）。

根因：面板的校验只覆盖数字范围和 JSON 形状（`client/form.ts` 的 `rangedNumberField`/`enumField`），不做加载期的跨字段与取值校验；而加载期（`resolveContextDefaults`、`resolveConfig`）按设计抛错。两个设计各自合理，叠加后保存非法值会让插件和它的卡片一起消失。

未修：需要改客户端校验（复用 `context-options.ts` 的 `check*`、`downloadDir` 绝对路径检查、新增一个表单级错误区和中英文文案），或让加载期对这些键降级成 `runtimeWarnings` 并保留卡片，涉及多个文件和 README 里“非法值抛出带键名的错误”的既定语义，不符合“单文件、有测试”的条件。建议下一轮作为独立任务做：保存前校验并在字段下显示错误；同时让插件在配置非法时仍注册卡片，在卡片顶部显示加载错误全文。顺带：`viewportMode` 目前是自由文本框，改成下拉可从源头避免拼写错误。

### P2-2 — 放宽 authProfile 后，已持有 context 的 session 注入不到新域名的 Cookie（已修复）

复现（`E-unr1`）：`target.open http://alt.localhost:47312/whoami authProfile=fx` → `runtime.set_auth_profile` 加 `localhost` → 同一 session 里 `target.open http://localhost:47312/whoami authProfile=fx`。页面回显 `{"cookie":null}`，没有任何提示。原因：context 创建时已按当时的 `allowedDomains` 裁剪登录态；`ensurePage` 看到 profile id 相同且选项没变就复用旧 context，收紧时 `changePolicy` 会关闭 session，放宽时不会。

修复（单文件 `src/browser-service.ts`，提交 `c650af9`）：`ensurePage` 比较 session 创建 context 时的 `allowedDomains` / `storageStatePath` 与当前生效值，不同则重建 context，`contextRebuilt.changed` 含 `authProfileScope`。测试 `policy-actions.test.ts`“a session that already holds a context starts a new one after its profile was widened …”；README 与 skill 的 `policy.md` 各加一句。真实 Host 复测（`E-widen-live-session-fixed`）：同一序列第三步回显 `sid=fx-localhost-cookie`，结果带 `contextRebuilt.changed=["authProfileScope"]`。

### P2-3 — 覆盖文件被忽略时，面板“清除覆盖”按钮是禁用的（已修复）
