# 2026-11-09 验证：设置卡片 RPC 通道改走公开 API（DSH 0.2.0-rc.2 / 0.2.1-rc.5 / 0.2.2-rc.1）

结论：把 [2026-11-05 记录](2026-11-05-dsh-0.2.2.md) 里依赖宿主私有 `register` 的回退，换成 [#49](https://github.com/anweat/dsh-browser/issues/49)（@shuaigekda）提出的做法，在三个真实宿主上都通过：经 `connectionCtx.extend({ webServer: connectionCtx.get('webServer') })` 读 `connection` 服务，再调公开的 `rpc.handle`。**所有宿主走同一条路径，不再依赖宿主的私有方法。**

执行者是开发者侧代理，不是独立验证者。只写亲眼看到的结果。证据在仓库外的 `research/experiments/dsh-0.2.2-2026-11-09/dsh-browser/`（`logs/`、`*.png`、`scripts/`）。

## 做法

`src/automation-assets-rpc.ts` 的 `connectionWithWebServer`：`rpc` getter 捕获的 `owner` 是读取 `connection` 的那个 Context，宿主在 `owner.webServer.register(route)` 里读 `webServer`；cordis 4.1 按 Connection 插件的定义位置检查 `inject`，所以普通 Context 上抛 `cannot get property "webServer" without inject`。派生 Context 把已注入的 `webServer` 作为自有属性带上（`Context.extend` 把 meta 属性直接定义在子 Context 上），`owner.webServer` 就在它身上解析。没有“先试 handle 再回退”的分支；挂载失败仍用 `console.warn` 报告通道与原因（不带 ANSI），effect 返回空卸载函数。

## 环境

- 宿主：`npm i --prefix <dir> @deepseek-ai/dsh@<ver> --registry https://registry.npmjs.org`，`0.2.0-rc.2`、`0.2.1-rc.5`、`0.2.2-rc.1`，全新 `DSH_HOME`（scratchpad），空的 `PLAYWRIGHT_BROWSERS_PATH`（走系统 Chrome）。
- 插件：`pnpm pack` 的 tgz，`dsh plugin --profile web add file:<tgz>`（过安装闸门），嵌套 pnpm 11.7.0（PATH 垫片）。
- 端口 3398；没有读写 `~/.dsh`，没有占 19387，没有跑模型、登录类命令、opencli 站点命令，没有读凭据。服务只杀自己启动的 PID，结束后 3398 无监听。

0.2.2-rc.1 另测：

- headless 完成的工具调用（无模型探针）：`browser_index`、`runtime.status`、`target.open`（本地 fixture）、`observe.read`、`observe.screenshot`、volatile 编辑后再 `browser_index` / `runtime.status` / `target.list`、`target.close` 均 `ok`；`act.click` 在无 agent 时按预期给出 `requires approval`。证据 `logs/probe-0.2.2-rc.1-nocfg.json`、`headless-probe-fixture.png`。
- Web 设置保存：关“启用 OpenCLI”并保存，profile 的 `cordis.patch.yml` 多出 `browser` 行 `config.opencliEnabled: false`；恢复默认再保存后文件与操作前逐字节一致；控制台 0 错误。证据 `browser-tour.json`、`browser-1..5-*.png`、`logs/patch-web-0.2.2-rc.1.before.yml`。

卸载用“释放 fiber”验证（探针用同一公开做法再注册同一通道），没有用 UI 里的禁用开关验证。证据：`logs/dispose-<宿主>.json`。卡片证据：`card-<宿主>.png`、`card-text-<宿主>.txt`、`logs/verify-web-<宿主>.json`。

## 与 #49 的说法对照

- 在 0.2.2-rc.1 上，`extend({ webServer: get('webServer') })` 经 `rpc.handle` 挂载成功：属实。匿名 401、带登录态 200、释放后移除，与 #49 一致。
- “用 `connectionCtx` 替换 `root` 不行”：本次没有重做这个反例（上一轮的试验里同样读法也抛错），文档里照此记录。
- #49 只在 0.2.2-rc.1 上验证；本次还证明同一做法在 0.2.0-rc.2 与 0.2.1-rc.5（cordis 4.0.5）上同样可用，所以不需要按宿主分支。
